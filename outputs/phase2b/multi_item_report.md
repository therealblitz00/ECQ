Generated by `src/phase2b_multi_item.py run` (2026-11-08). Light environment, no model run: the counts use the CSV columns, `masks.parquet` and the saved `person_crops.parquet`; the tests use the saved embeddings.

## 2. Crop rule per case

| case | action | note |
|---|---|---|
| person, item box found, box < 70% of the crop | crop to the item box | the existing rule; already reviewed |
| person, item box found, box 70-85% of the crop | crop to the item box | new suggestion; check on the sheet |
| person, apparel top / bottom or footwear, no usable box | crop to the garment region | heuristic by OUTFIT; check |
| person confirmed (lifestyle photo, or CLIP agrees), nothing usable | no crop: image block and palette off | tabular blocks only |
| OWLv2 sees a person on a packshot, CLIP does not | no action; check by eye | OWLv2 fires on flat coats and jewellery |

| several pieces (units > 1, not a pair) | no crop: flag | test below decides if the image block stays |

## 4. Recommendation

| photos | count | what to do |
|---|---|---|
| re-crop (already accepted) | 5 | keep the accepted crops of `person_crops_reviewed.json` (6, one on an untrusted photo) |
| re-crop (new, to be checked on the sheet) | 3 | accept or reject by eye in `multi_item_reviewed.json`, then embed on the vision machine |
| exclude from the image block and the palette | 44 | fall back to the tabular blocks; keep the row and the `exclude_image` flag (hard rule 3) |
| flag only: several pieces | 638 | keep the image block (see the test below) |
| check by eye: possible person (one witness only) | 359 | no action until looked at |
| leave alone | 8417 | packshots, pairs, lifestyle photos already cropped, rejected re-crops, worn-all-over garments |

- several pieces, different: nearest photos share the sub-family 67.3% of the time, against 66.9% for single-piece packshots (not lower).
- several pieces, identical: nearest photos share the sub-family 61.6% of the time, against 66.9% for single-piece packshots (lower by 5.3%).
- person (OWLv2): nearest photos share the sub-family 52.6% of the time, against 66.9% for single-piece packshots (lower by 14.3%).
- lifestyle (not a packshot): nearest photos share the sub-family 54.3% of the time, against 66.9% for single-piece packshots (lower by 12.6%).
- several pieces, different: team accuracy 78.2% with the image block, 73.3% without it (the image helps: keep it; small samples, see the pairs column).
- several pieces, identical: team accuracy 62.5% with the image block, 58.3% without it (the image helps: keep it; small samples, see the pairs column).
- exclude set: team accuracy 74.7% with the image block, 74.7% without it (no loss without it; small samples, see the pairs column).

Summary: re-crop only what a person accepts on the sheet; switch the image block and the palette off only for the exclude set (a confirmed person and no usable item box); for several pieces, flag and keep the image block, because the photo of the set is what the buyer compares and the encoders handle it as well as a single piece.

Palette: 252 trusted photos already have `reliable = False`; of the 317 photos with a person or lifestyle crop, 267 are unreliable already, and of the 44 photos in the exclude set, 43 are. The palette is measured on the product pixels of the same box, so a model's skin and clothes leak in. The rest of the exclude set (reliable = True today) should leave the palette block too (the engine then uses the other blocks). Several pieces: the palette of a set describes all its pieces, which is also what a buyer sees, so it stays.

## 5. What to run on the vision machine

1. A person opens `outputs/phase2b/multi_item_crops_sheet.jpg`, and writes the keys to keep in `data/embeddings/multi_item_reviewed.json` (`accepted`), the others in `rejected` with a reason.
2. Optional, only to widen the search: OWLv2 on the `check_possible_person` photos (needs the vision environment; the whole `persons` run took 16.6 h, `wall_seconds` in `person_crops.json`, and it rewrites `person_crops.parquet`, so do not rerun it as it is; a `--keys` option on the flagged photos only would be a small extension).
3. Embed the accepted crops. `phase2b_image_encoders.py embed` reads `person_crops.parquet`, not `multi_item_crops.parquet`, and always writes `image_<model>.npy`, so a small extension is needed first (not done here, existing scripts are not edited in this task): a `--extra-crops data/embeddings/multi_item_crops.parquet` option that applies `suggested_box` for the keys in `multi_item_reviewed.json` (`accepted`), and a `--suffix _multicrops` option so the output is `image_fashionsiglip_multicrops.npy` and never replaces `image_fashionsiglip.npy`. Then:

```
pip install -r requirements-vision.txt open_clip_torch
# control: Phase 1b crops only. Safe as it is: writes a NEW file image_fashionsiglip_nopersoncrops.npy
python src/phase2b_image_encoders.py embed --model fashionsiglip --no-person-crops
# treatment: person crops + the accepted multi-item crops (needs the extension above)
python src/phase2b_image_encoders.py embed --model fashionsiglip --extra-crops data/embeddings/multi_item_crops.parquet --suffix _multicrops
# light environment again: add the new stems to ENCODERS in this script and to the call below
python src/phase4_compare.py encoders image_fashionsiglip image_fashionsiglip_nopersoncrops image_fashionsiglip_multicrops
python src/phase2b_multi_item.py run
python src/phase2b_palettes.py        # palette on the same crops (light environment; check its output path first)
```

Compare the three FashionSigLIP files on the affected groups (section 3) and on the global team metric; adopt the crops only if the affected groups improve and the guards in `compare_report.md` hold. The control matters: it is the only way to isolate the effect of the person crops, which the saved files cannot show.
